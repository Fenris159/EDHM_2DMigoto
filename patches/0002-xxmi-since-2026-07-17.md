# Port XXMI v0.9.5–v0.9.8 (since EDHM 0.1.3-alpha.5 / 2026-07-17)

**Upstream range:** `af232a90` .. `326f64cf` (`origin/xxmi-base` = `xxmi/master`)

## Taken

INI command-list / pool / expression stack from XXMI 0.9.5–0.9.8:

- Resource pool overhaul (variables, spatial index, FIFO missing-UID, expiration, proxy chaining)
- `CommandArgumentReader` and parser refactors (hyphen subtract, UTF-8 names, `->` getters, locked vars)
- Expression features (`FRAME_NUMBER`, `DRAW_NUMBER`, `DISPATCH_NUMBER`, binary literals, unary funcs, static eval)
- Shared HackerContext staging/readback buffers
- `store` rewrite, command-list proxy mode, VB element-format/offset override commands
- Parser and null-check bugfixes (`GetIniBoolIntOrEnum`, missing resource path, GetCustomResource)

## Adapted (EDHM invariant)

XXMI now returns `HackerInputLayout` COM wrappers from `CreateInputLayout`. Elite + EDHM AVs if the game is given a wrapper. This port:

- Keeps the side-car cache; the game still receives the real `ID3D11InputLayout*`
- Stores shader signatures on the side-car so VB layout override commands can recreate layouts
- `DeferInputLayoutOverride` / `OverrideInputLayout` bind `GetOrigInputLayout()`, never the wrapper

## Not taken

- Wrapping input layouts as `ID3D11InputLayout` (unsafe for Elite)
- Replacing EDHM `GetTickCount64` Present timing / bounded log flush
- FlatHashMap ctor that allowed capacity 0 (missing-key probes would not terminate)
